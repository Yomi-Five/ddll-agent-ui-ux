# UI 通用基础

用于没有同类现行稿且库未覆盖时的布局与可用性兜底。参考格式塔、Nielsen 启发式、平台人机指南和 WCAG；适用版本及真实运行要求另查官方依据。

## 适用边界

- 用户最新要求、明确来源与所属库已规定的部分不重设计。按职责核需求、原型、现行稿和库，不用单一总排名覆盖业务变化。
- 场景例外留当前任务记录，不写进本文件。品味可在可用性边界内发挥，不能为风格删必要功能或说明。
- 以下数值是个人通用起点／可用性参考，不是所有端的实测尺寸；先沿现有 token，不凭兜底替换源稿。

## 间距与分组

- 无基准时优先 **4、8、12、16、24、32、48、64** 间距阶梯，以 8 为主节奏；界面选少量档位形成稳定节奏，不随手写碎值。
- 组内明显小于组间，优先形成至少约 **1:2** 的距离关系；按实际内容边缘判断，不能只看 gap 字段。
- 分组先用接近、对齐与层级，边框／卡片／分隔线仅在有作用时使用；布局能表达就不加说明，不以“归零后看不清”强制补卡片。
- 业务自建布局的生效间距及 padding 含 0 绑定现行库变量，匹配用途、值和 scope；缺档位报告，不造变量或改原值凑档。

## 操作与表单

- 无来源时按钮间距可从紧凑 8、标准 12、宽松 16 选择，危险操作与普通操作拉开；危险按后果判断，不将所有“取消”当危险。
- 同组一般一个最右填充主操作，优先收敛可见操作数量，次要过多时再考虑更多菜单；明确业务顺序、现行稿和平台例外保留，不机械按数量藏操作。
- 单独按钮不必是主按钮，角色依任务。紧密分段控件按库整体处理，不为了间距规则拆开。
- 表单按任务顺序分组，通常优先单列；确有相关成组字段或现行多列布局时沿其逻辑，不强制全改单列。
- 标签、内容首行、提示和条件字段关系明确，必要说明靠近对应控件。超长内容、省略／换行与布局按语义及来源处理。

## 适配与输入能力

- 断点由内容开始碰撞或信息层级需要改变的位置决定，不把设备型号或固定宽度表当普遍断点。
- 常规和适用窄尺寸检查导航、侧栏、表单、表格及浮层。大屏按内容限制行长，小屏保持必要功能；是否双栏、底部导航或抽屉由任务决定，不自动换导航。
- 文本行长可参考约 45–75 西文字符或 30–40 汉字，再按字体／内容调整。表格等二维内容可保留横滑，不擅自藏列。
- 不把关键操作或说明只藏在 hover；按真实输入能力区分触控／指针，混合设备不能只看屏宽。键盘需有等价入口及可见焦点。
- 触控目标可参考 Apple 44×44pt、Material 48×48dp；WCAG 目标尺寸要求按级别与适用例外核实，设计尺寸与点击热区分开看。
- 相邻点击目标留足间隔，危险操作避开高频触控区；不把体验建议当某平台硬性像素规则。
- 顶部遮挡、底部固定操作、横屏／分屏及输入法占位考虑真实安全区；不把某设备安全区测值写死到全部端。
- 移动网页小字号输入可能触发系统缩放，按目标平台核；必要时参考 16 CSS px 输入字号，不据此强制改原生 App 所有字体。

## 可用性与无障碍

- 状态变化及时反馈，等待、失败与恢复可理解；按任务选择进度／骨架／重试，不凭固定延迟一律加动画。
- 使用业务语言，保留返回／取消／撤销等适当出口；危险操作按真实后果预防，不到处加二次确认。
- 用可见选项与清晰分组减少记忆负担，选项数量按任务而非机械认知数字裁剪；减少步骤不能丢必要决策。
- 普通文字对比至少 **4.5:1**，大号文字至少 **3:1**；必要非文字控件辨识按适用要求 **3:1**。实际背景与透明度合成后核，见 [颜色规则](color-contrast.md)。
- 状态不能只靠颜色；结构、必要文字或图形共同表达，不额外堆重复标签。焦点可见且不被遮挡，键盘顺序与任务一致。
- 面向网页时，按适用 WCAG 要求核文字放大及约 320 CSS px 等效回流，二维表格等按例外处理；不把网页规则机械要求所有静态稿／原生界面。
- 运行态的键盘、读屏、触控、系统手势与输入法需在对应环境实测。静态设计只能验证表达与几何，不声称运行检查通过；自动检查不能替代人工判断。

## 出稿检查

并入主流程的合并检查，由当前检查者核视觉与结构，同时核内容与状态依据；复杂任务拆角色时分别由 Agent 3、Agent 4 承担，不另加重复验收。只检查本轮适用项：分组与层级、操作角色及危险区分、间距及绑定、必要状态、常规／窄尺寸、长文本、输入能力、安全区与对比度。空／加载／错误／权限先遵守主 skill 的状态来源硬性要求，仅在旧稿／指定原型有依据或用户明确授权新增时表达，不为清单补无关稿。
