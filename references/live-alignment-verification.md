# 现有界面与线上对齐

用于既有稿修正、线上对齐、字段／说明／状态与组件规则核验。先核完整表现再改，不扩展无关页面改版。

## 先分清依据负责什么

- 用户最新明确要求确定本轮边界。业务内容与行为、视觉样式、组件规则、演示数据可各有来源，分别核验，不将任何一份当整页替换授权。
- 需求确定范围及明确变化，原型表达流程／字段／分组意图，指定现行稿提供未改内容及视觉基准，所属库提供复用结构和状态能力。不同端、语言、版本的同名稿不可互换。
- 未要求改的文案、单位、空格、顺序、按钮角色与布局保留；新增模块复用完整同用途容器关系。库默认与实例实际表现不同，查变体、覆盖及条件，不直接清成默认。
- 线上指实际运行界面或指定线上截图，不能把 Figma 稿未经核实称作线上。查看标出位置和对应状态，不用相邻项、旧测量或“接近”代替。
- 来源不可访问、状态不可复现则标未验证；实际无法查明的业务冲突只暂停依赖部分，不用演示数据、近义词或惯例推导业务。

## 完整字段与数据语义

修改相关列表／字段，在任务记录按范围核「字段及顺序 → 来源／状态 → 条件 → 文本／链接／帮助 → 枚举与口径」，不画成产品说明。

- 检查横向溢出、固定列、字段设置和权限，区分可选、默认、当前勾选及权限字段；不把未勾选当不存在，也不把所有可选强加进稿。
- 链接核真实可点击对象与样式，无目标占位按普通文本，不因编号相似统一变蓝。链接视觉不代表需要 Figma 原型连线。
- 提示核入口、完整正文、条件、展开态及位置；优先库已有说明能力，不以布尔属性已开或默认截图证明交付。
- 枚举从来源读取准确文案、顺序和表现，不用近义词改业务状态，不根据示例日期推算状态，也不把普通状态自动做彩色标签。
- 每行代表的业务主体、合并关系、共享信息及计数口径先明确；重复值不证明需要合并，视觉合并不等于业务合并。
- 演示数据与展示结构分别处理，按已确认占位／数据保留，不编造缺失明细或分摊值。行数变不自动改业务总数，不为凑画面重复累计。

## 只改内容时保留组件样式与使用条件

- 保留完整结构、分段字体／字号／行高／颜色、文本样式及绑定；混排不能统一赋值成一种样式。字符串正确或实例仍有关联不能代替逐段验证。
- 图文、图标文本、复合操作组按完整形式复用，不退化成纯文案或底层控件拼接；图片须实际加载、可见，比例和排版按源。
- 组件能展示不代表业务应展示。默认按钮、提示、汇总和标识按当前类型、状态、权限及条件核，不把默认开启的旧能力带入。
- 链接、状态、品牌标识、帮助图标分别核语义和实际色；用户否定上轮结论时刷新当前来源，不继续沿被否定样式。

## 浮层、空状态与反馈复核

- 复现实际展开态，核分组、换行、内边距、边框、圆角、投影、箭头、锚点及裁剪；只按组件名字猜不合格。见 [浮层与迁移核验](restoration-migration.md#浮层嵌套状态与失效组件)。
- 空状态先查所属库真实示例及适用条件，区分整页／容器、无数据／无搜索结果等；核必要文案、操作、插图、背景和对齐，不为套模板堆三段说明。
- 区分实例调用错误与共享能力缺口：前者使用现有能力，后者按 [优先回库](component-spec-rules.md#组件修改优先回库)，不批量覆盖掩盖。
- 有效反馈持续保留；先定位错误属性，再对本轮同因区域有边界复核，明确例外。未定位不猜根因，颜色问题不扩为文案修改，宽度问题不扩成重排。
- 最后修改后核当前来源、实际属性及本机完整上下文和关键截图；结构变化同时核数据主体、行粒度及计数，不能只查无重叠。
- 已授权明确漏项修复后重验；纯评审或范围外／新决策只报告。分别说明内容、视觉、结构、发布和同步实际状态，不把局部截图概括全量一致。
