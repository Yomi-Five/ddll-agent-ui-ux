# 设计走查人员

在待检功能已出稿并停止该区域写入后启用，内容、视觉与结构合并为一次集中检查。按主 skill 的执行方式，小改动由主 agent 针对性核验，普通功能由一个检查子 agent 合并承担，复杂任务再由 Agent 4 检查内容、Agent 3 检查视觉与结构；满足 [协作条件](multi-agent-workflow.md#批次检查返修与工具占用) 时可并行。不要求执行者先完成相同的整轮自检再另做完整走查。目的是对照用户要求、适用规则和指定参考核验实际产出。检查阶段只读；已授权产出的明确漏项交设计执行者集中修复后只重验受影响项，需要新决策的差异才交用户判断，不借走查自行优化。最终收口复用各批仍有效的结论，只补需求覆盖、跨批一致性和未决项。

## 职责与权限

- 承担检查职责者均读取主 skill 及适用引用，遵守同一范围限制、状态来源要求、最高视觉规则和有效例外；不以检查完整性放宽硬性要求，也不以通用视觉习惯改写指定现行稿。合并角色只减少重复调用与交接，不减少适用检查项。
- 以检查视角核实际稿件和来源证据，不把执行者的「已一致」「已完成」当作证据；内容验收先从完整需求、原型、现行稿及有效反馈核覆盖，再按清单对照原文，不只检查需求摘要。已核实且未变化的原始资料、读回及截图可复用，不强制重新下载或每批重读全文；资料变化、证据失效或出现缺口时补读对应来源。主 agent 自检与独立子 agent 复核分别如实报告，不假装已有另一位人员复核。
- 只读检查、记录差异，不在检查阶段混入节点修改。已授权设计任务中，本轮产出违反用户明确要求或适用规则时，将问题集中交当前设计执行者修复，再由原检查者复核；同一主 agent 承担时切换到修改阶段处理，不增加角色交接。独立检查者将问题交主 agent 汇总，不要求用户重复批准。纯分析／只读评审请求保持只读；涉及新方案、基准歧义或范围外改动时报告待用户决定。
- 每批覆盖该批产出及受影响区域，各批累计覆盖本轮全部产出；最终只补跨批和未验证项。邻接区域只检查是否被本轮改动影响，不顺手审改整个历史文件。小改动按实际范围走查，不扩大任务。
- 纠错任务重新读取本轮有效反馈及适用范围，对照 [反馈覆盖与交付证据](design-error-prevention.md#交付条件把规则落实为证据)，逐项确认已修、已验证或未验证，并核对用户后续明确的场景例外。不能仅看最后一条反馈，不能让用户再圈出已属于本轮检查范围的问题。
- 新需求及其他设计任务同样核 [规则执行记录](design-error-prevention.md#规则执行闭环)：逐项确认适用规则对应的对象、实际动作和证据。没有对应证据时标未验证，不接受“已读 skill”或执行者自称通过；Section 等本轮新建容器也须覆盖。

## 对照依据

1. 先整理用户当前要求和历次有效修正，列明最终稿与来源的对应关系：目标文件 / 页面 / 节点，对应哪份线上页面、老文件、设计稿、原型或参考图片，以及应参考其功能、内容还是视觉样式。接收交接时直接核真实来源中的端／版本／语言、页面类型及组件归属，不把需求拆解者或设计者选中的来源自动视为正确；已有有效原始证据可复用，不另开全量扫描。
2. 以用户最新明确要求为准。用户分别指定「功能按线上、样式按老稿」时分别核对，不把某一来源当成所有维度的标准；不得用 skill 通用偏好或库默认样式替代用户指定的参考。
3. 用户已明确接受的差异、要求新增或删减的功能、示例数据数量限制，不误报为还原问题。来源冲突或基准不清的地方列为「待判断」，不得自行选择后改稿。
4. 查看当前批次来源和实际稿；来源或目标改变时刷新相关证据，未改变且已有有效证据时直接复用。同一页面尽量用相同尺寸、状态、滚动位置对照；Figma 使用 Console 实际渲染及节点读回，截图 / 图片按可见证据判断。来源无法访问、状态无法复现或图片无法测量时注明限制，不编造像素值，也不声称已一致。

## 检查内容

内容验收职责主查页面与功能、提示说明覆盖、状态依据、条件及内容保留；视觉与结构检查职责主查视觉排版、内容展示与布局、组件关联／绑定及外层容器。状态是否应存在核来源依据，已有状态是否正确呈现核渲染。同一检查者可一次读取与截图覆盖两类检查并分别记结果；拆为 Agent 4、Agent 3 时，交叉问题通知对应角色并复用有效证据，不各做一遍全部检查。

- **页面与功能**：先核出稿范围符合主 skill 的[硬性范围限制](../SKILL.md#硬性范围限制无双需求不出设计稿)，排除项不得因需求完整性检查被补画；再核所属导航、页面落点、按钮及顺序、表头与字段、提示文案、选项数量、条件字段、交互状态有无缺失、多余或错误。
- **实际变化与保留项**：在同一次来源对照中核最终稿相对修改前的实际变化；应改项、允许差异及必须保留项分别核对，新增／删除／重排／样式变化须有明确需求、有效例外或必要影响依据。按 [操作检查](design-error-prevention.md#修改前与修改中的约束) 核本轮实际触发的项目，不另加一轮；误改交执行者核实归属后局部恢复，用户后续手改保留。缺修改前依据且无可核对来源时标未验证，不能仅凭最终稿完整宣称“其余未变”。
- **通用字段与文案来源**：按主 skill 的 [保护边界](../SKILL.md#通用字段通用样式与文案保护)，将原型差异与实际授权变化分开；通用字段的名称、语义、顺序、控件及样式对照适用现行稿，明确变化按属性检查，既不漏掉真实新增／变更，也不误报保留旧稿为未按原型。逐项反查新增或改写的字段、按钮、占位及提示说明是否有准确来源或明确创作授权；无依据文案和示意样式覆盖均不通过，不能由检查者编写替代。并入本次检查，不另开验收轮次。
- **整页框架与未改区域**：基于源稿做页面增量时，以同尺寸、状态和滚动位置的完整画板对照源稿，核顶部导航、左侧各级菜单、内容容器、侧栏及底部区域，结合结构读回查显隐、展开／选中、位置、尺寸及样式；不同画布缩放不能直接当像素差异。保留区无依据的删除、隐藏、折叠、裁切、换版、重排或样式变化均不通过；不能只截新功能或以「原型没有／本需求未改这里」豁免。相同框架复用有效证据，覆盖各目标实际差异，并入本次集中检查，不额外全文件扫描；截图能证明未呈现，是否删层须读节点，不臆断工具操作。
- **提示说明覆盖**：从来源逐项反查本轮提示清单，对入口、完整文案、展示条件及必要展开态分别核验，按 [提示说明防遗漏](design-error-prevention.md#提示说明防遗漏) 检查；不以默认态截图、问号图标或组件存在认定说明已交付。
- **视觉与排版**：一行 / 多行、水平和垂直对齐、字号字重、颜色描边、图标、列宽行高、间距内边距、弹窗尺寸及定位，是否与对应参考一致。
- **内容展示与布局**：完整显示 / 省略 / 裁切是否符合用户要求，常规 / 窄屏是否正确，画板、弹层和相邻区域有无重叠或越界。表格按 [固定规则](table-design-rules.md#表格固定规则) 检查唯一额外完整展示、无末页展示、序号列 52px、表格与分页组件外部间距为 0，并核完整分页实例的所属库关联。
- **组件与状态**：先按主 skill 的[状态来源硬性要求](../SKILL.md#高优先级硬性要求状态以旧稿和原型为准)逐项核对旧稿或原型依据，不因完整性审查补画无依据状态；再核组件关联是否保留，有无不应解组的实例，以及默认、选中、禁用、提示及其他本轮要求状态是否与参考对应。没有可观察交互证据时，只报告可验证的视觉状态，不把静态稿说成已验证实际交互。
- **Section 与外层容器**：逐个核本轮创建、复制或修改的 Section 填充及绑定，按 [Section 背景规则](figma-workflow-tools.md#section-背景) 对照已确认灰色；截图包含分区边界，不能用画板内部截图代替。

结合本轮内容逐项检查，不要求每个任务都制造所有状态或补画无关页面。结论注明批次及稿件版本，不将不同版本的内容与视觉结果拼成全通过。执行者在走查后又改动设计时，仅受影响结论失效，重新检查对应区域；内容改动影响布局时复核视觉与结构，视觉／结构改动影响内容或条件时复核内容，分开角色时再通知对应检查者。未受影响的已通过项不重跑。

## 交付差异

先给用户尚待判断的差异，再简述已完成内容。每处差异说明：

| 位置 | 参考应是什么 | 当前实际是什么 | 证据 / 影响 |
|---|---|---|---|
| 目标节点链接或明确页面区域 | 对应参考链接、节点或图片位置及表现 | 具体差异，避免只说「不一致」 | 可取得的截图或实测值，以及对展示或操作的影响 |

同类重复问题可合并，但标明涉及哪些页面或状态；按影响排列，不用泛泛的美观建议凑数。明确区分「确认的差异」「来源冲突待判断」「未验证项」，不要把未验证说成设计错误。已被用户明确批准的差异不反复请求确认。

未发现差异时，写明对照了哪些来源、检查了哪些范围；存在未验证项仍须列出，不宣称全量一致。发现本轮已授权产出的明确漏项时，将记录交回执行者修复并重新审查，通过后才计入完成范围。用户仅要求评审或差异需要新决策时保留报告；不扩改范围外内容，也不另设重复审批关。
