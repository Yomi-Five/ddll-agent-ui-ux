# 多 agent 分工、交接与恢复

适用于主 skill 的轻量执行与按需四角色协作。执行方式以主文件的「小改动直接完成、普通功能合并检查、复杂任务按需四角色」为准，不将下列角色职责理解为强制启动四个子 agent。本文件只规定通用执行方式，不存具体需求、节点、文件 key、项目路由或工具版本参数；实际任务卡和进度保存在所属任务工作区。

## 共同前提与调度

- 主 agent 与全部子 agent 先读 [主规则](../SKILL.md)，再按职责读本轮适用引用。主文件中的范围限制、状态来源要求、最高视觉规则、明确例外、来源分工及共同设计约束全程生效；任务卡、检查建议、工具故障及其他 agent 的结论不能覆盖它们。只有用户明确变更相应限制时才调整，泛称「做完整／继续」不构成变更。
- 主 agent 按最轻适用方式执行或派工，汇总有效反馈、维护一份当前记录、处理冲突和安排返修；小改动可直接完成并针对性核验，普通功能将视觉／结构与内容检查交一个子 agent，复杂任务再拆角色，不额外叠加整轮自检。是否独立复核按实际执行者报告。子 agent 不再派生其他角色或自行扩展任务。
- 四个是职责角色，不是同时运行的要求。按当前可用并发容量、依赖和工具占用分阶段启动；角色完成交接后可释放实例。需要继续时先接续现有适用实例，任务过长或上下文失效时使用同角色新实例并交接；接替设计写入前确认旧执行实例已停止写入，不能让两个 Agent 2 同时操作，也不能只把整个长任务转移到另一个 agent。
- 相同来源、规则及未失效证据直接复用，不每次交接重新扫描文件、查库或下载需求。完整来源须可访问，验收者首次核对需求覆盖后逐项查对应原文；仅在资料变化、证据失效或发现缺口时补读，不每批重复通读全文。不能以节省时间省略首次完整读需求、来源核对、必要读回或本机渲染检查。
- 纯评审只读，可由主 agent 或一个检查子 agent 合并执行，不因本流程创建文件或修改设计。「无双不出稿」不自动禁止用户明确指定范围内的只读读取和差异报告，评审发现也不构成创建或补画无双稿的授权。多 agent 不可用时说明实际限制，按相同边界依次执行相应角色，不伪称有独立子 agent 验收。明确范围及授权内连续推进，不新增模式或逐批审批。

## 四个角色的交付边界

以下是职责边界；轻量执行时由同一主 agent 承担需求核对和设计执行，内容与视觉／结构可由同一检查者合并完成。只有实际跨执行者时才交接，不为角色名称制造任务卡或往返汇报。

### Agent 1：需求核对与拆解

- 完整读取需求正文、表格、验收及有效反馈，再核关联原型和现行稿；摘要、标题、搜索片段不能代替全文。确认资料是否完整，缺失项标明影响。
- 先执行无双范围限制，再逐项核旧稿／指定原型中的状态依据；排除项仅作业务理解，不进入出稿和补齐清单。把实际设计变化、删除、沿用、仅业务逻辑变化及明确不适用项分开，不将每条文字需求都变成一张页面。
- 按端／版本／语言定位实际来源与依赖，形成「需求项 → 原始位置 → 目标对象／来源旧结构 → 允许变化／必须保留 → 验收方法」。字段、选项、默认值、条件、完整提示与必要展开态均须可追溯；人民币币种补齐等明确例外同步传递。
- 按可独立交检的功能拆批并说明依赖；不能为拆批增加页面或状态。查不到的来源列具体缺口，不以未定位证明不存在，不让用户整理可查询事实。

### Agent 2：文件准备与设计执行

- 首批先核授权落点、查重并复用已有需求文件；新文件按主规则先建立并置顶更新记录，再添加／启用所需库并确认可调用，随后复制必要业务稿与依赖，再开始修改。定点修改和定稿回迁仍走各自既有规则，不机械创建新文件。
- 复制范围与最终展示范围分别判断。复用完整旧结构、业务自有母组件及嵌套依赖，保持规范库远程关联、变量、主题、样式、富文本、图片与覆盖；不能只按展示清单删掉仍有依赖的沿用结构，也不整库或整历史文件搬运。
- 每次按一个功能批次的任务卡设计，保持未授权内容不变；创建时落实适用规则，不先画错误临时稿。默认静态交付和副本连线清理、字体、Section、间距绑定等仍按主规则及适用引用执行。
- 每批交付实际目标节点、来源映射、已做／未做动作和需检查区域；核实际写入与目标归属后交检，不以工具成功当验收通过。改错文件、关联损坏等会扩大错误的问题即时处理。
- 仅当前承担此职责的设计执行者写入已授权设计目标，并负责检查后的集中返修；可以是主 agent 或一个子 agent，不能同时写入。共享库修改仍需原有授权和影响核对，发布由用户操作；不因返修另建替代稿、打散组件、造变量或扩大业务范围。

### Agent 3：视觉与结构检查

- 按 [设计走查](design-reviewer.md) 只读比较实际来源和本机最终渲染，核对齐、间距、字体、颜色、图标、尺寸、裁剪、布局、浮层及完整可见边界；覆盖本轮 Section 和组件集展示层。
- 核组件及嵌套关联、属性、变量绑定与解析值、主题和富文本分段。实际外观与结构分别取证；不因绑定非空、节点数量相同或无重叠认定全通过。
- 在授权范围与指定来源内执行规则习惯，不以个人审美重设计旧稿；尤其不得用辅助文案补救布局。只返回具体差异、位置、依据、证据和复核结论，不直接改稿。

### Agent 4：需求与原型验收

- 独立对照完整需求、指定原型、现行稿及用户有效修正，复用仍有效的原始资料，不只核 Agent 1 的摘要或 Agent 2 的完成声明；正向查应有内容，反向查多画、无依据改动和误删保留项。
- 核范围、端／版本／语言、流程、字段及顺序、控件类型、全部选项、默认值、条件、完整提示、必要状态与金额币种例外。原型没有不代表可以删旧稿，需求文字提及也不自动授权新增旧稿和原型都没有的状态。
- 只读交付逐项覆盖结果、已确认差异、来源冲突和未验证项；有证据才通过，不用视觉整齐代替内容正确。发现需求拆解漏项时，由主 agent 在既有授权内补充当前范围并交设计执行者处理；同一执行者承担时直接更新必要记录，不额外制造任务卡或交接，不自行扩画。

## 交接与当前记录

所有角色共用主 agent 维护的一份记录，任务卡是其中的当前批次部分，不另建重复台账。小改动不写额外交接文档；连续执行时只维护必要的来源、目标与未完成项。实际派工才让接收者获得：

| 交接内容 | 最小必要信息 |
|---|---|
| 规则与范围 | 主 skill 路径、本轮适用引用、硬性要求、排除项、有效用户修正／例外及其依据、允许变化和必须保留项 |
| 原始资料 | 完整需求及原型的可访问位置或已完整取得的资料、实际旧稿／库来源与各自负责维度、受影响对象必要的修改前依据；资料缺口与已核实结果分别标明，检查者可直接核原始证据，不只接收转述 |
| 目标与批次 | 实际文件／页／稳定根、端／版本／语言、来源到目标映射、功能批次边界、依赖、交检条件及禁止修改对象 |
| 当前进度 | 实际已做动作、未完成动作、稿件版本／最后修改范围、执行者与当前工具占用、阻塞及下一步 |
| 检查与证据 | 需求覆盖、实际变化与保留项及视觉／结构结果，截图和读回对应的对象与版本，待返修问题、同因适用范围／例外及复核责任；复用同一份记录，不按角色重做 |

状态统一为「待执行」「执行中」「已执行待验收」「待返修」「已验证」「阻塞（缺口）」「不适用（依据）」。内容、视觉、结构／绑定分别记结果；库发布、实例同步和云端保存另记，不合并推断。

## 批次检查、返修与工具占用

1. 以完整功能组织出稿与检查，同一来源和依赖的已完成批次可合并为一次交检；不按字段或每个小弹窗反复拆派。设计执行者记录各批实际结果与未决项，交检区域停止写入；内容、视觉和结构合并集中检查，按执行方式由同一检查者承担或分给 Agent 4、Agent 3，不先叠完整两轮自检。
2. 来源、范围和稿件版本一致且工具访问互不干扰时，两类只读检查可并行。不能边改同批稿边验；共享 Console 连接、当前文件／页面或原生 UI 焦点时，由主 agent 安排串行占用，读操作也不能抢切编辑者的目标。记录本任务当前占用者与目标，由占用者完成操作并交回结果后释放，再交给下一个角色；该记录不是跨任务锁。发现其他任务占用时先核实其是否已结束或存在可独立使用的目标通道，无法确认就标记依赖阻塞，不抢切焦点，继续不依赖该连接的工作。交接或切文件后按 [工具规则](figma-workflow-tools.md#目标连接与分批调用) 最小核实，不每个节点重复查连接。
3. Agent 3、4 返回问题时带批次、目标位置、预期依据、实际差异、证据和影响。主 agent 合并同因问题，区分明确错误、来源冲突、新决策和未验证；角色结论冲突时回到原始依据核实，不投票、不自动服从某一角色。
4. 已授权范围内的明确问题交当前设计执行者集中修复，原检查者复核受影响项；内容变化若影响布局，复核视觉与结构，视觉／结构变化若影响内容、状态或条件，复核内容。分开角色时通知对应检查者。相关旧证据失效，未受影响的结论复用，不全量重跑。只有需要新决策、权限或确有资料冲突时暂停依赖部分并说明缺口，继续独立工作。
5. 不要求每个执行批次验收通过才能继续独立批次：写入结果已核实、没有会扩大错误的问题，且下一批不修改待检区域或其共享依赖、工具互不干扰时，可继续出稿并集中交检；共享依赖不明或发现结构／范围错误时先解决。待检、阻塞项仍保留且不计完成。最终由承担 Agent 4 职责的检查者补核需求覆盖、跨批内容一致性及未决项，承担 Agent 3 职责的检查者仅补跨批视觉／结构变化和失效证据；主 agent 汇总，不另做重复整轮验收。

## 中断恢复与交付条件

- 每个可恢复批末、角色交接及可控中断前，更新实际目标、当前版本、已完成动作、未完成动作和工具状态；不逐调用写流水。意外中断后从最近记录核实实际结果，不假设中断前的记录覆盖了最后写入。
- 恢复或更换角色实例先读当前记录、有效规则与原始资料，再最小核实目标、最后修改及证据有效性。超时可能部分写入，先从稳定根读回再补缺；不重复创建文件、更新记录、复制稿或整批重跑。沿用原有工具恢复次数与停止条件，不因更换 agent 重置成无限重试。
- 用户中途修正时，主 agent 更新唯一有效基准，通知相关角色并撤销受影响任务卡和旧结论；不删除已授权保留的内容，不让新实例继续执行失效方案。
- 交付前每个适用需求项都有来源与目标对应，内容、视觉和结构检查均有当前结论；明确问题已修复并复核，待执行、待返修、阻塞及未验证项单列，不计入已完成范围。全范围尚有未完成项时不能汇报全量完成。
- 不以四个角色均回复「完成」代替证据；本机编辑、静态验证、实际交互／Motion 播放、发布、同步及云端保存分别按实际结果报告。不承诺会话结束后自行运行。
