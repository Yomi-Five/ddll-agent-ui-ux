# 单 agent 执行与恢复

由同一个 agent 完成需求核对、目标准备、设计、验收、返修和交付，不启动子 agent。纯评审保持只读；新需求文件、定点修改及定稿回迁按[执行流程](design-workflow.md)的适用阶段处理。内容、视觉与结构均须核验，但不将自检称为独立复核。

## 依次执行

1. 完整读取需求、表格、验收和有效反馈，再读取 HTML 原型；按端、版本、语言定位真实现行稿及依赖。区分明确变化、必须保留和排除项，记录「需求项 → 原型位置 → 来源旧结构 → 目标对象 → 允许变化／保留项 → 验收方法」。保留主 skill 的无双范围限制、适用边界状态和人民币符号例外。
2. 查重并按主规则准备目标；新文件先建立并置顶更新记录，再启用所需库并确认可调用。按原型页面及流程顺序逐个打开对应来源文件，复制粘贴所需页面及必要依赖，保留完整旧结构、业务自有母组件、规范库远程关联、变量、主题、样式、富文本、图片和实例覆盖。首次修改前核对副本的结构及渲染；不搬运无关历史稿。
3. 根据需求及原型要改的内容制定修改方案，按原型顺序和复杂度拆成稳定、可恢复的小批逐步修改，不一次写入全部页面和状态。只改授权变化，原型未要求修改的内容保留旧稿；适用边界状态和人民币符号按既有例外处理。每批读回实际写入并记录进度；目标、范围或结构错误以及会扩大的异常立即处理。
4. 需求设计完成后，按原型顺序分批逐页验收，对照完整需求、原型、现行稿及有效修正，逐个核字段、顺序、控件、选项、默认值、条件、提示和必要状态。正向检查应改项有无遗漏，反向检查多画、无依据改动和保留项是否受损；同批合并检查渲染、布局、组件关联和变量绑定。不能仅以原型未显示就删除旧稿内容，也不能以摘要或工具成功代替来源与实际结果核对。
5. 在授权范围内修复明确问题，复核受影响项及其相关内容、视觉或结构；未受影响且仍有效的证据复用。来源冲突、必要资料或组件缺失、超出授权的事项说明缺口，暂停依赖部分并继续可独立工作。最终核跨批一致性和未决项，交付实际完成与验证结果，未验证项不能计为完成。

## 记录、工具与恢复

- 设计执行／评审首次开始按[恢复登记](session-recovery.md)关联当前聊天和已有任务记录；恢复 Hook 完整注入最新入口时视为本轮已读，仍读取适用引用并核实际写入。完成、取消或切换无关任务时更新该聊天恢复状态，不改其他聊天。
- 在既有任务记录维护来源、目标、有效要求与例外、批次、实际已做和未做、稿件版本、验证证据、阻塞及下一步，不另建重复台账或逐调用写流水。状态区分待执行、执行中、已执行待验收、待返修、已验证、阻塞和不适用；内容、视觉、结构、发布与同步分别记录。
- 检查阶段以只读视角记录差异，返修时切回修改；记录问题位置、预期依据、实际差异及证据。证据因修改失效时重验受影响项，不重复整轮验收。
- 发现其他任务占用共享连接或界面焦点时，先核实是否已结束或有独立通道；无法确认则标记依赖阻塞，不抢切焦点。切换文件后按 [工具规则](figma-workflow-tools.md#目标连接与分批调用) 核实目标。
- 批末及可控中断前记录实际目标、最后修改、未完成动作与工具状态。恢复时先读记录和有效来源，核实最后实际写入；超时可能部分写入，先从稳定根读回再补缺，不重复建文件、复制或整批重跑。用户修正时更新有效基准并使受影响旧结论失效。
- 交付时分别报告实际检查结果及未完成、未验证、阻塞项；本机编辑、静态验证、交互或 Motion 播放、发布、实例同步和云端保存各自取证，不互相推断。
