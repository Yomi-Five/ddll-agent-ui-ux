# 官方组件与示例复刻检查

适用于用户指定官方 Figma、官网组件或示例，要求按自己的规范复刻。验收同时覆盖对源一致与实现有效，不能只以内部结构有效认定还原正确。

## 1. 先完整取证，再建立对应关系

- 以用户指定的来源和节点范围为准。明确指定某份 Figma 时，以该稿为复刻依据；官网只作补充，不能擅自用另一版本覆盖它。先看完范围内全部行列、底部内容及主题面板，再确定示例清单，不从首屏推断总数。
- 每个源示例记录：类型、交互状态、填写/选择状态、校验状态、主题、文案、标签数量、前后图标、清除按钮、箭头、选中标记、菜单及搜索框显隐。每条映射到目标实例；“支持某属性”不代表该示例的默认配置已还原。
- 用户规范控制字号、尺寸、圆角、变量和展示排版；它不自动授权删掉源的槽位、组合状态或示例内容。区分规范适配与意外差异。有实际冲突且会改变结果时，列明冲突再确认。
- 源结构读取受限时，继续用可访问的可见内容对照，明确哪些只验证了外观、哪些内部行为不可验证，不宣称结构或交互完全一致。示例数量、标签数量只属于当前源，不写成其他组件的固定要求。

## 2. 状态关系先建模

- 将类型、交互状态、内容/值状态、校验状态分别梳理，确认哪些互斥、哪些可叠加。源上错误可与聚焦、禁用、激活共存时，用独立校验属性表达，不能将错误塞进互斥的交互状态轴而丢失组合。
- 不凭翻译认定 `Active` 等于已填写、聚焦等于选中；按源的实际结构和行为判断。保留本地规范要求的已填写、禁用已填写等状态，不用新增源状态覆盖已有状态。
- 按源组合逐项核对，而不是看目标变体数量是否更多。不要制造源与本地规范都未要求的笛卡尔积或重复视觉状态。

## 3. 图标看实际形状，取色覆盖实际绘制节点

- 图标名称只是候选线索。实例化前核对预览或矢量形状，优先追溯现有正确实例的主组件；发现名字与外观不符，记录本轮使用映射，不顺手重命名全库。
- 改图标颜色时遍历实际承载 `fills` / `strokes` 的节点，不能只处理 VECTOR；BOOLEAN_OPERATION / Union 等也可能绘制可见图形。核对实例和子层覆盖、透明度，以及各目标主题下的实际可见性。
- 示例局部问题优先修对应实例；不要为修一个示例改共享图标母组件，影响其他页面。

## 4. 主题看解析色与合成结果

- 变量绑定存在只是结构检查。读取目标主题下解析后的背景、文字、占位符、图标与描边颜色，并核对实际层级与对比；不能由 `bg-white`、`bg-muted`、`placeholder` 等名字推断最终颜色。
- 语义变量的解析色与角色不符时，先找同库同主题的正确用法，在现有合适变量内选择并记录适配原因。文本仍用所属库的文本语义变量；不擅自修改共享变量或用死色覆盖。
- 半透明效果在示例实际背景上核对，并与不透明版本并排看。白色在白底上降低透明度可能仍完全同色，数值小于 1 不等于视觉符合参考。
- 对照包含填充和描边，尤其搜索框的细边框、占位符与已填写内容的区分，以及深色主题下关闭图标的可读性。
- **固定色变量不会随主题自动切换**：逐层读取受影响区域的 `fills` 和 `strokes`，记录变量所属集合、当前有效模式、解析后的 RGBA 及透明度。检查分隔线时同时覆盖容器的单边描边和独立线条。绑定了变量或父层设为 dark，不代表固定色原语也会变暗；不能用文字变白来推断边框已适配。
- **母组件与实例覆盖分别核对**：母组件样式修改后，检查目标实例是否仍保留旧填充、描边或效果覆盖。只修用户指定区域及其必要依赖；发现其他问题先说明，不扩展为全库改色。实际选择依据当前来源，不把一次色阶匹配推广到其他场景。

## 5. 切换实例后重新验收覆盖

- 操作顺序：创建/替换实例、设置变体与主题，再恢复文案、槽内容、图标和显隐覆盖。最后读回嵌套实例的实际 `visible`、尺寸、主题和内容；属性面板值不能代替这一检查。
- 切换变体可能让隐藏菜单重新出现，尤其要检查关闭态、禁用态与展开态，避免关闭控件被菜单撑高。检查包含浮层和阴影的完整占用边界。
- **显隐恢复是整块区域重新验收的触发点**：footer、菜单或插槽由隐藏变为显示后，检查它自身和可见子层的背景、文字、图标、按钮、边框、分隔线及间距。“无背景”只清空区域填充，不等于隐藏 footer，也不等于删除按钮填充或分隔线。修好按钮对比度后，还要核对所在区域剩余的视觉层。
- 静态示例与可交互示例分别验收。继承的原型切换可能跳回未定制的默认变体；按任务要求处理并验证，静态展示不能汇报为搜索等交互已实现。


## 6. 写入与失败恢复

- 紧接写入前确认文件、页面、目标节点及类型。用户并行替换节点后，不能继续用失效 ID 或当前无关选区；只有当前上下文能明确证明替换关系时才转到新节点，否则确认目标。保留页面框架实例及原生 SLOT，不打散或盲目重建被删节点。
- 创建属性/示例前查找本轮已有记录，保存创建的 ID。任何异常或超时后先读回实际结果，判断哪些修改已落地，再补做或清理本轮部分产物，避免重复属性、重复示例。
- 将内容写入与最后的选区/视口操作分开。页面已切换导致选区设置失败，不代表内容创建失败，不应重建整个批次。

## 7. 汇报前两类检查都要通过

- **对源检查**：逐项清单对应、状态组合、默认配置、各主题、图标形状、填充/描边和可见内容，对照源与目标画面；源可读时补结构数值对照。
- **实现检查**：真实实例、属性/槽绑定、文本样式与变量、实例切换后的覆盖、含浮层与阴影的边界、无重复产物。
- 清单漏项或未验证项必须明确写出，不能用“变量都绑定了”“无重叠”“变体更多”替代还原验收。只有两类检查都达到本次约定范围，才能汇报完成。
- **截图必须用于发现问题**：在实际页面实例上查看整个受影响区域，逐项比对上述清单；截图中出现过亮分隔线、低对比文字等异常时，定位并修复，或明确列为未解决项。工具返回截图成功、布局 diff 无变化，都不能证明主题配色正确。
