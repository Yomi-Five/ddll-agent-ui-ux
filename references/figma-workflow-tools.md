# Figma 工具与流程

操作前按本轮需要读取；具体 API、参数、权限和能力以当前工具文档为准，不保存某项目命令、ID 或报错流水。

## 读取、编辑与本机验证的分工

| 操作 | 首选路径 |
|---|---|
| 读结构、查库、建文件、受支持的文件复制 | 官方 MCP；先查实际能力，不假定有旧接口 |
| 设计编辑、文字写入、编辑中的文件内克隆 | Console MCP，使用已确认目标连接 |
| 最终截图与字体渲染验收 | Console 本机截图，避免云端字体回退误判 |
| 跨文件保真复制 | 先查官方支持；不足时用已有授权涵盖的原生界面路径，保留关联 |

- Bridge 断开暂停依赖它的编辑、文字和本机验收，不改用官方写图顶替。前期读取、建文件和受支持复制不受其前置约束。
- 非文字库资源导入／绑定若 Console 受限且当前官方接口支持，可在 Console 已连接时用官方导入，再本机读回与截图；不扩大为官方文字或布局编辑。
- 原生 UI 操作前确认文件、窗口及焦点，其他任务占用导致焦点变化时先核实际状态，不向未确认窗口发送快捷键。

## 目标、连接与分批调用

- 按 [协作规则](multi-agent-workflow.md#批次检查返修与工具占用) 由主 agent 调度工具占用，设计目标仅当前设计执行者（主 agent 或承担 Agent 2 职责的子 agent）写入；其他角色只读也不得抢切其共享连接、页面或 UI 焦点。内容、视觉与结构尽量在一次工具占用中合并读回和取证，交检区域停止写入，切文件、交接或恢复后最小核实实际目标；不以角色任务卡中的旧目标代替实际连接。
- 初次、切文件、故障和断点恢复后最小核验文件及页面；调用支持目标 fileKey 时显式传入。同一目标持续有效不每步列连接或重查库。
- key 与归属来自用户链接或实际查询／创建返回，不编造。节点未找到可能是页面、旧子层或参数问题，不直接认定 Bridge 断开。
- 用户已重连先验证连接列表和目标最小读取，区分无连接、路由错、页未切、参数错、权限和超时；确需用户操作才一次说明，不循环要求重连。
- 按页／功能区域批量读写，在当前工具时限内完成，不一条巨型脚本处理全任务，也不每节点截图。适用超时值取当前文档，不固化版本参数。
- 写入失败／超时可能已部分完成，先从稳定根查内容、数量和属性，再补缺。初始化失败不继续依赖未定义结果；一次有针对性恢复后同故障仍在，停止同参数盲试并记录当前状态，继续独立工作。
- 截图失败先核活动文件、页与稳定根，修正后最多再试一次；仍失败如实标未截图验证，不以属性读回补成视觉通过。
- 槽位或实例内部移动后重新从稳定根取节点，动态页面使用当前支持的异步读取；不手拼深层 ID。遇失效子层逐项保护读取，不为绕过报错打散组件。
- 先复用已核实资源，再按需导入；不要因导入慢就用无关联副本。跨工具写入可能有同步延迟，读回确认生效后取证，不重复造节点。
- 本机完成不代表云端已保存；未同步时保持工作可恢复，不关闭／刷新丢弃工作，分别报告编辑、验证和云端状态。

## 字体、默认值与可见差异

- 写文字先加载目标实际字体，富文本按段保留。字体不可用沿已有替换授权；无授权不静默替换或只用可加载字重冒充原稿。
- 云端字体和截图可能回退，本机数据及实际渲染作为字体核验依据。字重读回正常不能否定偏粗观感，继续查绘制层、分段样式、缩放、重叠和文本样式。
- 仅针对必要节点尝试重新加载并恢复同字体，修后对来源同用途文字与本机截图；不把一次技术故障变成所有复制必刷字体的规则，不改无关文字试错。
- 新建／复制检查实际生效的裁剪、描边是否参与布局、尺寸模式、最小／最大约束、字体及文本样式。布局不稳定先解决生效层，再读最终尺寸，不凭属性默认推断。
- 图片 hash 非空不证明素材可见，核真实填充、比例、可见区域和渲染。内容居中按完整可见范围，不只看图片几何。
- 改布局时仅清理本轮失效约束、旧命名及过期批注，不新增说明块；保留无关内容。

## 飞书需求与附件

- 用适用飞书工具先完整正文后 HTML，按当时专用技能的认证和命令处理，不复制历史租户或脚本。
- wiki 链接先解析实际文档，再读分页／截断；正文嵌入文件与知识库子节点分别检查，子节点为空不代表无原型。
- 附件按实际资源类型下载，主动读取可取得资料，不提前让用户重新上传。临时文件按任务需要保存，不留凭据。
- 权限不足、附件不存在和类型／命令错误分别定位，不能凭一个空结果或错误推出文档没有内容。

## 画板排布与重叠验收

1. 列当前批全部独立展示区域及周边既有边界，最终累计覆盖本轮产出；不只抽查根画板。
2. 换算页面绝对坐标，读根及未裁剪可见后代、浮层、菜单、投影和补充展示的完整占用，尊重显隐与裁剪。有意遮罩／弹窗叠放不当画板碰撞。
3. 每行按实际最下边界和统一展示间距排下一行，横向同理；不用预估高度、旧尺寸数组或固定行步长。
4. 字体、换行、Hug、变体、图片或尺寸变化后，受影响几何结论失效；最后写入后重读尺寸，修受影响行及后续排布，Section 容纳完整内容。
5. 最终边界计算和本机总览／边界放大截图都通过才能称无重叠；数值空列表不能否定截图碰撞，尺寸仍变化先解决稳定性。
6. 只修本轮产出的展示位置与容纳尺寸，邻稿作避让依据；断连、超时或范围未覆盖标待验证。

## Section 背景

- Section 是分区容器，不是产品界面，使用已确认灰色，不用白色；沿本文件已有同类灰色及绑定，没有则查已确认来源，不临时自选。
- 创建／复制时显式落实实际填充和绑定，不能保留未核默认白。只改 Section，不把画板、弹窗、卡片底色一起改灰。
- 不嵌套 Section，分区用位置与间距，不加无用说明。验收逐个读本轮 Section 的填充／绑定，截图含分区及白色画板外边界；内部截图不算已核背景。

## 更新记录

- 业务设计文件维护更新记录。新需求文件创建后的第一步是沿来源建立或复制更新记录页，并置于页面列表首位；完成后才能复制业务稿。需求首次进入每个目标文件登记一次。先查重，后续纠错、补状态和改文案不加行或补正文，明确要求补记才改。
- 更新记录置页面列表首位，紧随官方页面分隔线，保留其他页相对顺序；新需求文件及复制后即核。使用当前支持的官方分隔能力，读回实际 divider 状态，不拿画布线或普通命名页顶替。
- 沿当前文件／复制来源的字体、富文本、尺寸、间距和链接表现，复制适合的既有条目，只改必要日期、需求名和实际作者，不硬编码作者或行尺寸。
- 新记录链接指向当前需求，改完读富文本链接并核原模板未改；已有条目错字不借机改。登记文字使用 Console 及真实字体，不以云端回退硬写。
- 不凭顶层节点数判记录页为空，读取真实行内容。最终截图核新行与相邻样式，并分别报告已登记、已存在或未验证。
