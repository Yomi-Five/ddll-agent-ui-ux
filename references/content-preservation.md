# 范围、来源与内容保护

适用于既有稿增量、改字、内容替换及来源冲突核对；与新需求流程配合使用。仅修改本轮授权对象及实际受影响属性，验收同时核变化与保留项。

## 硬性范围限制：无双需求不出设计稿

**无双需求不出设计稿。** 这是跨任务生效的硬性出稿范围限制，优先于需求文档、附件原型中的出稿范围及本 skill 的视觉与流程建议。混合需求中可读取无双内容以理解业务规则和端间依赖，但不得为无双创建或补画页面、弹窗、状态及专用组件；仅对其余已授权端的实际设计变化出稿。不能因“完整覆盖需求”、已有原型或用户泛称“做这个需求／继续”而纳入无双稿，也不重复询问是否出稿。只有用户明确撤销或变更本限制时才可调整。

## 来源优先级

**来源优先级：样式以旧稿 > PRD > HTML 原型。** 用户最新明确要求先确定本轮边界；样式、未改内容及视觉基准取指定现行稿，其次 PRD，最后 HTML 原型；业务规则、字段与状态以 PRD 为准，**PRD 与原型冲突时以 PRD 为准**，并在任务记录中登记冲突。所属库提供复用结构和状态能力。通用建议只填尚无依据的空白，不能删除明确需求，也不能让原型重写无关旧稿。

## 通用字段、通用样式与文案保护

- **原型有差异不等于本次要修改。** 对适用端／版本／语言中已有的通用字段及复用区域，默认保留指定现行稿的字段名称、业务含义、顺序、控件、文案和实例实际样式。先核字段语义、上下文及完整旧结构，不凭同名或近义词认定同一字段；原型中的简写、示意外观、占位及省略不构成改名、换样式或删除授权。
- 只有用户明确要求、本次需求可追溯的业务变化、已核实的原型变更标注或明确例外，才把对应对象及属性列入允许变化；原型独有的明确新增项仍按来源意图设计，不能以「旧稿没有」漏掉。仅看出原型与旧稿不同，不能推断其为明确变更；「按原型做／直出」本身不授权覆盖通用字段和样式，「完整／优化／统一」也不授权扩改。字段确需改名、增删或调整业务含义时落实该项，未涉及的样式及其他字段继续保留；需要的局部空间调整不扩大为重新分组或整页改版。
- **新增或改写文案必须有来源或明确的文案创作授权。** 字段名、按钮、占位、Tooltip、辅助说明、空状态和错误提示均适用；沿用准确原文与分段样式，不以「更完整／更易懂／符合习惯」自行补写、润色、同义改名或带入库占位文案。业务概念首次出现且无准确措辞时查现有资料；仍缺失只暂停该项并说明缺口，不把猜测或「待确认」写进产品，也不删已有必要业务提示。
- 原型与现行稿的通用字段／样式差异，在既有任务记录中归入「明确变化／沿用／冲突待查」；明确属性边界及文案来源，在旧结构副本上最小修改。按上述规则已能判定沿用的差异直接保留，不逐项问用户；真实业务冲突查明不了才问具体缺口，继续无依赖项。
- 在既有集中验收中反查所有实际字段、文案及样式变化：有来源且属授权范围才通过；以现行稿核保留项、以需求及有效原型意图核变化项，不能仅凭「与原型一致」通过。确认本轮误改时局部恢复，保留用户后续手改与其他授权变化。无双范围、状态与边界、「让布局解释」、人民币币种补齐及组件／发布限制继续生效，不因来源优先级取消明确例外。
