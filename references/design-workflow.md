# 设计执行流程

新需求、新流程及整页设计读取本文件，并读[范围与内容保护](content-preservation.md)。旧稿局部改字或样式调整按入口路由，不机械执行建文件、复制整页等不适用步骤；准备、执行、验收及续做按实际阶段取用。来源定位见[来源与落点](figma-map.md)，库依赖见[库来源与依赖](figma-libraries.md)。

## 明确需求直接执行与技能分流

- 已授权且来源、范围和落点可核实的新需求、旧稿增量、组件复用、纠错、迁移和续做，直接按本 skill 推进，不再问「是否采用方案／是否开始／是否按既定流程执行」。完整读需求及原型、定位现行稿、查重准备需求副本、建立更新记录、启用所需库、最小修改和验收，是本 skill 已规定的执行路径，不另设方案选择关。
- 调用其他 skill 前先核适用边界。不能仅因「新需求」「新增组件」「创意工作」或工作量大而进入 brainstorming；其方案比较、逐段批准、规格文档审批、提交和 writing-plans 流程，不适用于此处已明确的执行任务。用户当前指令及既有授权先于 skill 的一般流程建议，不把另一个 skill 的通用审批要求变成本任务的新前提。
- 仅用户明确要求头脑风暴／方向比较，或存在无法从当前要求和来源解决、且尚未获准自主决定的实质设计方向时，才进入对应探索流程。已有授权自主决定的常规布局、技术路径、分批和角色选择直接执行；不能把只做说明稿、整套重做或破坏组件关系等不满足已确认要求的方案列为选项，再要求用户选择正常执行路径。
- 确需提问时只问具体未决事实或决策，说明影响对象和缺口；能从现有资料查询的先自行查明。来源冲突先按来源优先级判定；必要资料／组件不可用或超出既有授权时，仍按原规则仅暂停依赖部分，继续独立工作；不把取消重复审批解释成放宽范围、发布或组件约束。
- 若已误发多余确认，纠正后直接接续已授权未完成项；错误提问本身不产生新的审批条件，也不重复建文件或重做准备。用户明确要求暂停或变更范围时按最新指令处理。

## 执行流程

### 1. 读完整需求，再读原型

由同一 agent 形成可追溯到原始资料的范围对应关系。需求全文及原型只获取并整理一次，后续复用有效原始资料；验收仍须对照来源，不以摘要代替原文，也不要求每批重新下载和通读未变化全文。

- 飞书需求先用适用的飞书工具完整读取正文、表格、规则、验收及原始名称，分页／截断继续读取；全文读完再检查和下载关联 HTML 原型。检查正文嵌入文件，不能以知识库无子节点判定无附件。无 HTML 则按完整文档推进，不虚构原型。
- 摘要、标题和原型均不能代替需求全文。必需资料不可读时说明具体缺口，暂停依赖它的绘制，继续可独立的准备。
- 区分新增、修改、删除及仅沿用的流程，列适用端／版本／语言、实际变化、必要状态和组件依赖。再按[状态与边界](common-design-rules.md#高优先级硬性要求状态与边界按功能补全)列出每个功能需补的边界状态。已有入口不等于要重画内部流程，数据规则改变不自动产生新设计页。
- 选项控件记录类型、全部选项、默认值和条件；提示记录入口、完整文案、触发条件和必要展开态。核对动态拼接后的完整文案，不只摘字段名。
- 识别本轮金额字段并在出稿时补齐币种符号：人民币金额统一带「¥」，即使原型或旧稿漏写也主动补齐；零金额、负金额、明细和汇总均覆盖，负金额写为「-¥金额」。不改原数值、精度及分段样式，不重复添加已有符号；明确为其他币种时保留其币种。此项是沿用原型／旧稿内容的明确例外。

### 2. 定来源、边界与当前批次

同一 agent 确定来源、范围和功能批次，核对实际目标并准备副本、更新记录及库；来源定位缺口须查明。

- 先执行[硬性范围限制](content-preservation.md#硬性范围限制无双需求不出设计稿)，再确定适用端和当前批次；排除的内容仅作业务理解，不进入出稿清单。
- 实时核对来源文件、页、目标及实际样式，不按文件名、记忆或静态索引猜现行版本。区分端、语言、版本与维护状态。
- 新需求默认在独立需求文件中编辑所需来源的副本，位置固定为「订单来了」团队 →「项目用」项目，名称沿需求原名；先查已有文件，续做不重复创建。新文件创建后的第一步是建立更新记录页并置于页面列表首位，完成后再复制业务稿，详见[更新记录](figma-workflow-tools.md#更新记录)。来源只读，定点修改按用户指定文件，定稿回迁按回迁规则。
- 按原型页面与流程顺序通过后台工具定位对应来源文件，将本次所需页面及必要依赖复制到目标文件；核实来源与目标，避免遗漏或重复复制。保持完整旧结构及组件关系，不搬运无关历史稿；后台能力不足按[工具规则](figma-workflow-tools.md#读取编辑与本机验证的分工)记录缺口，不前台打开文件或用系统剪贴板复制粘贴。
- 所需设计稿复制到目标文件后、开始业务稿修改前，在目标文件中添加／启用本需求会用到的全部组件库，确认所需组件可检索、可插入后再改稿，详见[库来源与依赖](figma-libraries.md#新文件启用组件库)。续做时核实并补齐尚未启用的所需库，不重复添加。规范库组件保持远程关联；业务自有的本地组合母组件随依赖完整复制，不能只搬实例，也不能把规范库克隆成本地库。
- 修改或沿用既有界面前，必须先建立当前批次的「目标对象 → 对应旧稿节点／明确例外 → 允许变化／必须保留 → 执行动作 → 验收方法」，核实际端／版本／语言、页面类型及母组件归属；只保存改动对象与实际受影响区域的必要修改前内容、结构、属性及渲染依据，供改后对照，同类对象可批量采集并复用，不全文件备份或另建台账。页面、弹窗及流程内部步骤都须定位实际来源；找不到时记录具体缺口，不把未定位当成不存在或重新绘制的依据。来源定位、尺寸实测、内容对账和组件追溯由执行者完成，不让用户整理可查询事实。
- **整页复用先核完整副本**：基于源稿改页面时，定位实际完整画板及父容器，不能只取中间业务模块或换用另一版页面框架。将复制核验并入既有读回：对照源稿的完整画板渲染及关键结构，确认顶部／侧边导航、内容区、侧栏和底部区域的存在、显隐、相对位置、尺寸与样式未因复制失真；相同源框架的证据可复用，目标副本的对应关系仍须核实。复制已缺失或变形时先修复，不在错误底稿上继续批量派生；若仅能取得图片，不把截图铺底或近似搭建称为完成可编辑源稿复用。
- 已有范围、来源与授权直接开始；不重复确认常规复制或逐批续做。确实无法查明的业务冲突、资源缺口或授权不足只暂停依赖部分，继续独立工作。

### 3. 按功能完成一批设计

**按原型顺序准备页面 → 制定修改方案并逐批出稿 → 需求设计完成后分批验收 → 修正并重验受影响项。**

- 一批覆盖可独立查看的功能及必要弹窗／状态，按复杂度分批；不同时铺开全部端和状态，也不为凑批次制造页面。
- 批次是可恢复的执行单元；按原型顺序和页面、功能复杂度拆成适合工具稳定处理的小批，逐批修改，不一次执行所有页面和状态。批末或中断前记录实际节点与未完成动作；共享依赖问题或会扩大错误的异常即时处理。
- 新需求设计与既有稿修改均优先用官方 MCP，新增或需编辑文字统一先用 `Noto Sans SC`，按[字体流程](figma-workflow-tools.md#字体默认值与可见差异)验证可加载能力并保留目标对应关系。设计期间不因本机字体或 Bridge 连接暂停独立工作；先完成设计阶段内容、视觉与结构检查并修复明确问题，再集中用 Console 后台恢复目标字体／文本样式，复核受影响布局和本机渲染。临时字体是明确的阶段性例外，不放宽内容、组件、变量与未改区域保留要求。
- 创建时直接落实组件、变量、中文命名和容器规则，不先画错误临时稿；按 [修改操作对应的检查](design-error-prevention.md#修改前与修改中的约束) 选择适用项，沿实际操作做必要局部读回，详细对照与截图并入一次集中检查，不每个节点另开验收。改错文件、组件损坏等会扩大错误的问题即时处理。
- 表格创建、恢复、合并及批量修正沿 [表格设计规则](table-design-rules.md)，按 [表格创建执行方案](table-creation-workflow.md) 连续完成当前功能；核完整交付范围、筛选、完整分页组件及数据保留，将内容、结构和视觉并入本批次验收，不能只修局部表格便称整页恢复。
- **沿用不等于重画**：存在适用旧稿时，必须先复制或复用完整旧结构，再在副本做本次明确变化的最小修改；不能仅参照字段重新搭建。既有任务记录中的允许变化须限定到区域及属性，其余页面框架默认保留：顶部导航、左侧各级菜单、选中／展开状态、内容容器、侧栏、底部内容及其尺寸、间距、字体、颜色、背景、描边和组件关系。不能因原型省略、与新功能无关、清理展示或适配方便而删除、隐藏、折叠、裁切、换版或重排；未单独展示的沿用流程不等于可从页面中移除既有结构。通用排版习惯及原型的示意样式不能覆盖未要求变化的旧稿。只有用户明确要求重设计，或已查明旧结构无法承载本次变化时，才在已授权范围内调整必要结构，并记录受影响对象和依据；局部容量不足不授权替换整页框架或删除导航。
- 在对应画板副本迭代，不另画一套整页示意。只展示有实际设计变化或必要差异的稿；未改旧流程不必重复单列，但仍作为复用基准。删除或移出旧稿副本前，核它是否仍被本次入口、流程步骤、状态或组件依赖；不能只因“无变化”移除仍需沿用的结构，更不能删除后另画替代。
- 保留未授权修改的容器关系、字段顺序、富文本、单位、空格、数据、样式及布局习惯；新增模块先找同用途完整结构。库默认值不能覆盖现行实例已确认的表现。
- 需要新风格且没有基准时找少量相关参考，说明借鉴维度；方向尚未确定才澄清，不增加常规审批。先结构与层级，再颜色，最后材质与动效。
- 默认交付静态设计，不新增演示连线；清除副本带入的演示交互和流程起点，来源不动。必要展开态仍表达。明确要求可点击原型时才保留或新增连线，不因此穷举操作历史和数据组合。
- 清理副本演示交互或用户要求全文件去连线时，覆盖目标全部页面、隐藏节点、本地组件及嵌套实例的 reactions 和 flowStartingPoints，读回确认目标范围无残留；不以隐藏连线代替删除，不影响来源、组件关联和视觉状态。

### 4. 内容与视觉验收及反馈闭环

需求设计完成后，由同一 agent 按原型顺序分批逐页验收，逐个核对字段和内容，与需求、原型要改的内容及旧稿对比，检查错、漏、多画和误改；原型未要求修改的地方保留旧稿，已明确的边界状态及人民币符号例外继续执行。每批合并检查内容、视觉与结构，结论对应同一版实际稿；发现问题后修复，只重验受影响项。具体要求见 [设计走查](design-reviewer.md)。

- **内容轮**：先按出稿前的对应关系核对旧稿复用和允许差异，再检查范围、字段、选项数量／完整文案、顺序、条件、状态及提示；逐项核对金额币种符号，包含零金额、负金额及汇总，不能以原型漏写为验收通过依据；反查克隆带入的多余功能与无依据改动。不是把「原型没有」的现行内容全部删除。未完成来源核对的对象标为待验收，不能因组件完整、画面整齐或无重叠而报完成。
- **视觉与结构轮**：以只读走查视角，对比实际来源和最终本机渲染，核组件／嵌套关联、属性、分段文字样式、变量及解析值、间距、完整边界和适用尺寸。Section 与组件集展示层也属于产出。
- **实际变化核对**：在同一次检查中，将最终结果与修改前依据、明确需求及有效例外比较，核应改项已落实、保留项未受损；实际新增、删除、重排和样式变化均须有依据。确认属于本轮造成的无依据变化时，仅恢复该处，保留用户后续手改及其他授权变化；来源或修改归属不清时先核实，不整页重置。没有修改前或可核对来源证据的项标未验证，不凭记忆声称保持原样。
- 工具成功、实例存在、绑定非空、数量相同、截图存在或无重叠，均不能单独证明整体通过；读回证明实际结果，仍须和来源预期比较。
- 明确漏项在已授权范围内直接修复，只重验受影响项；同因覆盖本轮适用对象，保留场景例外。颜色问题不扩成改文案，容器问题不扩成重排内容。
- 用户指出“不一样”时重新取指定来源的同位置和状态，核实际绘制层与渲染；数据正常不能否定可见差异。未定位不猜根因，被否定的结论退出当前基准。
- 最终收口只补全需求覆盖、跨批一致性及未决项，复用仍有效的证据，不再重复整轮检查。纯评审只报告；已授权产出不能止于检查清单。

### 5. 连续推进与交付

- agent 在任务工作区维护一份当前记录：来源、目标、有效要求／例外、批次与稿件版本、执行及检查状态、阻塞和下一步。失效方案和完成结论移出当前状态，历史仅供追溯；不逐工具调用写流水，也不写入产品界面。
- “继续”、上下文恢复或工具恢复后，从记录最小核实目标，只补未完成项。技术故障不撤销已有授权，不重做复制或重复造稿；不承诺会话结束后自行运行。
- 区分待执行、执行中、已执行待验收、待返修、已验证、阻塞与不适用；内容、视觉、结构、库发布、实例同步、云端保存分别报告。只声明实际通过的范围。
- 交付简述改动、影响与验证；未验证或需用户处理的项明确列出。任务索引有变化时更新该任务记录，不把具体项目资料写回 skill。
