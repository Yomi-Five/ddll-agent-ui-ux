# 来源定位与编辑落点

本文件规定定位方法及用户明确指定的长期工作区落点约定，不保存一次性团队文件清单、项目路由、文件 key 或节点 ID。实际索引存所属任务工作区。

## 定位来源

- 从用户给的链接、需求名称、当前可见稿及维护关系查来源，核实文件、页、Section、目标端、版本、语言与当前状态。名称相同不证明内容或用途相同。
- 分开记录「读取来源」与「编辑目标」；原稿、参考、归档稿和新需求副本不是同一角色。用户指定旧稿时读取对应实际内容，不以相邻稿或库默认代替。
- 先查必要模块及其直接依赖，不无条件扫描整个团队。已有索引只作线索，操作前实时核实受影响目标；索引过期只刷新相关范围，见 [按需扫描](figma-rescan.md)。
- 来源唯一且已有授权就继续；用可查询信息无法消歧时，说明具体候选及差异，只暂停依赖部分，不要求用户重新整理全部来源。

## 确认落点

- 新需求在「DDLL-项目管理测试 → 测试用项目」中新建独立文件，名称沿需求原名；先查是否已存在，续做复用，来源文件保持只读。新文件创建后先按[更新记录](figma-workflow-tools.md#更新记录)建立并置顶更新记录页，再复制业务稿。所需页面在相应副本迭代，不借近处无关画板承载。
- 定点修改在指定文件；定稿回迁到对应主文件的现有模块，只补缺失。端、语言、版本分别定位，不因一端有页面就扩画另一端。
- 实际位置与权限通过当前工具返回核实，不能只凭名称或记忆。文件／库 key 只能来自用户链接或真实查询、创建结果，不编造。
- 归档沿当前文件已有或用户指定位置；没有明确要求不自行跨文件移动、归档或删除来源。清理展示前核查组件依赖和独有状态。

## 记录与验证

任务记录保存来源到副本／目标的映射、适用范围、例外及当前状态。复制后核内容、依赖、实际归属和最终渲染，见 [业务稿复制](app-pc-rules.md#新需求副本与依赖)。索引变化留在任务记录，不回写为通用 skill 条目。
