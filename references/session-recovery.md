# 设计会话自动恢复

用于设计执行、只读评审首次登记、断线接续及上下文压缩恢复；普通改稿不反复加载本文件。此集成不改变任务范围、编辑授权或原有验收要求。

## 开始与记录

- 在设计执行／评审首次开始时，用当前可用 Python 运行本技能的 `scripts/design_resume.py activate --record <已有任务记录绝对路径>`。脚本从 `CODEX_THREAD_ID` 取当前聊天 ID；环境未提供时使用 Hook 提示中的 `--session-id`，不按目录猜聊天。
- 先复用并更新已有任务记录；确无记录时按主流程建立唯一当前记录后登记。首次尚未建立记录也可先 `activate`，准备完成后再关联 `--record`。登记可重复调用，只更新当前聊天的恢复元数据，不改记录正文。
- 每个功能批次及可控中断前，把目标、实际完成／未完成、有效例外、验证状态和下一步写入原任务记录。Hook 仅保存聊天、状态和记录路径，不另存业务台账；不要仅依赖退出时保存。
- 全部适用项完成并验收后运行 `complete`；用户取消或明确切换无关任务时运行 `deactivate`。需要接续时重新 `activate`。这些操作只更新当前聊天状态，不改 Figma 或原任务记录。

## 自动加载与降级

- 安装在宿主的 `SessionStart`（启动／恢复／压缩／分叉）和 `UserPromptSubmit` 处理器，按聊天状态自动注入最新 `SKILL.md` 原文；完整注入视为本轮已读入口，再按路由读取适用引用，不重复用工具读同一入口。入口版本变化使旧缓存失效，压缩后强制重新注入。
- 同轮重复事件去重；恢复与紧随其后的首条输入共用一次入口，下一轮重新加载。引用不会随入口全部注入。
- Figma 工具的 `PostToolUse` 可为当前聊天自动登记，作为首次手动登记的补充。尚无标记的旧聊天仅在宿主提供的当前聊天记录中查实际 Figma 调用；只看最多末尾 8 MiB，不靠聊天名称、目录或用户文本中的关键词判断。
- 历史格式不是稳定接口；查不到实际调用时，仅提供条件式恢复指引，不猜任务类型。已有记录能证明是设计任务时先手动读入口并登记。自动读取失败时明确提示手动加载；不得把失败当作已经执行。
- 恢复后先核记录、当前目标及最后实际写入，防止超时造成重复创建；纯评审仍只读。换新聊天时须明确关联原任务记录，不能自动继承同目录另一聊天的状态。

## 宿主配置与验证

首次接入或排查安装时读[GPT 与 Codex Hooks 接入说明](codex-hooks-setup.md)，配置结构见[可复制的 JSON 模板](../examples/codex-hooks.example.json)；普通设计恢复不重复加载安装说明。

在宿主的现有 Hooks 中合并处理器，保留其他处理器及信任配置。处理命令使用当前有效 Python 和本脚本的绝对路径；入口注入阈值设为 5000 tokens。状态保存到当前 Codex home 的 `design-skill-state/`，按聊天 ID 隔离，仅存恢复元数据，不写回共享技能。

新增或变更 Hook 须按宿主要求由用户审核信任，不自行修改信任哈希或绕过审核。未安装／未信任时，依靠全局指令手动读取入口并登记，不声称自动恢复已生效。脚本使用 macOS／Linux 的文件锁，其他宿主须先适配并验证。

维护时用可用 Python 运行 `scripts/test_design_resume.py`，核恢复、压缩、仅输入“继续”、同轮去重、入口更新、聊天隔离、旧聊天补登、结束／取消及失败提示；模拟事件通过后，还须取得宿主真实触发证据才能声明实际恢复已验证。
