# 设计失误预防与反馈闭环

适用于新需求的提示说明拆解，以及既有稿迭代、用户纠错及批量修改。本文件记录可执行的设计约束，不保存项目节点、业务样例或操作日志。单点修改只核改动处及实际受影响区域，多页任务覆盖本轮适用稿。

## 规则执行闭环

skill 中的适用规则必须执行并验收，不能只阅读。按主 skill 的 [轻量执行与按需协作](multi-agent-workflow.md) 分配职责，默认合并内容、视觉与结构检查；小改动不另启子 agent，普通功能只用一个检查子 agent，复杂任务再拆四角色。由主 agent 在同一份任务进度记录中汇总以下对应关系；子 agent 返回结果，避免并发覆盖。同类规则按功能合并，小任务可合成一行，不额外向产品界面写检查文案，不另做一套重复台账。

`来源与例外 → 目标对象 → 允许变化／必须保留 → 预期与实际差异 → 证据与状态`

1. **选出适用规则和基准**：从用户本轮要求、skill 主流程及已路由的相关 reference 提取，覆盖页面内容、复用组件和本轮新建容器。核实际来源的端／版本／语言、页面类型和组件归属，分别确定业务、视觉与复用依据，不凭名称或上一个角色的结论选源。仅对当前改动对象和实际受影响区域，保存修改前完整内容、必要结构／属性、组件关系及渲染依据；同类对象可批量采集，已核实且有效的证据复用，不全文件快照、不另建台账。来源不可访问或有冲突时标出具体缺口，不用估算或相邻版本代替。纯分析／评审任务只记录检查与结论，不因此获得编辑授权。
2. **把规则放进动作**：修改前确定目标对象、允许变化及必须保留项，按下节操作表选择适用核对项。每项新增、删除、重排或样式变化须对应明确需求、用户指令、已明确例外或承载本次变化的必要影响；已授权自主设计时记录所选方案及理由。在产生对象的那一步落实属性、内容及绑定，不依赖工具默认值或未经核实的继承；已有对象符合时保留并验证，不强制重写。阻塞时继续不依赖缺口的已授权工作，不增加逐节点或逐批确认。
3. **证据按功能集中采集、逐项对应**：已完成且同一来源和依赖的批次可合并交检，待检区域停止写入后，一次集中核内容、视觉与结构。内容检查从完整来源正向查应改内容是否齐全，再用修改前依据反查实际新增、删除、重排、样式及结构变化是否均获授权、保留项是否受损；不能从已生成的内容或需求摘要反推应有范围。确认无依据变化由本轮造成后只恢复对应对象／属性，保留用户后续手改和其他授权变化，不整页或整实例重置；归属不清先核实，缺对照证据标未验证。视觉与结构检查对照基准查属性、组件关系与最终渲染，覆盖外层容器和受影响区域。同一检查者合并执行，复杂任务拆角色时按协作条件并行；结论须对应同一版稿件，不再叠完整自检，不每批重读未变化全文。一次批量读回或截图可支持多项已实际检查的规则；截图存在不代表每条规则通过，工具写入后的读回只证明写入结果，不能代替与来源比较。
4. **按状态交付**：使用“待执行”“执行中”“已执行待验收”“待返修”“已验证”“不适用（依据）”“阻塞（缺口）”。内容、视觉、结构／绑定分别记录实际检查结果，发布与同步另记；存在绑定缺口时可报视觉通过，不得称规范全部通过。实测附来源，估算标估算，未复现或未知不写成确定根因。最后一次修改使相关旧证据失效，只重验受影响项；当前状态替换被否定结论，不以追加日志保留两套有效说法。
5. **审查后完成修复**：已授权任务中，发现本轮产出漏掉明确规则，由主 agent 汇总问题交当前设计执行者集中修复，原检查者复核受影响项；检查阶段不直接改稿，也不能以“走查只读”为由停在建议。主 agent 同时承担执行与检查时直接切换阶段，不另做交接。只有用户仅要求评审、新决策、修改范围外对象或真实阻塞时，才保留报告或待判断状态。已核实写入且没有扩大错误或共享依赖风险时，可继续独立批次并集中交检，不逐小批等待；全部适用项均有结论后再作最终交付，完成声明不覆盖尚未通过的项。

以下是把既有规则转成动作和证据的示例，适用时纳入本轮记录；具体样式仍以各 reference 和用户当前要求为准：

| 规则对象 | 执行动作 | 验收证据 |
|---|---|---|
| Section 背景 | 创建／复制时沿用已确认灰色的实际填充和绑定 | 本轮各 Section 的填充及绑定读回，分区与白色画板边界的截图；不能只截画板内部 |
| 组件复用或修改 | 追溯实际来源，在授权落点完成组件能力或实例调用 | 主组件／实例关系、属性及内容读回，以及受影响状态的实际渲染；发布、同步另记实际状态 |
| 颜色与主题 | 按所属库和现行稿设置要求的样式或变量绑定 | 实际绘制层的绑定、解析色及本轮要求主题截图；不能只看变量名 |
| Tooltip 与说明 | 将入口、完整文案和必要展开态落实到对应页面 | 对照来源逐项检查文案、显隐条件、锚点及完整浮层边界 |
| 布局与间距 | 设置本轮要求的布局关系、间距及绑定 | 最终几何、绑定及完整可见边界读回，常规／适用窄尺寸截图 |

## 通用原因：为什么会反复画错

| 原因 | 典型后果 | 执行约束 |
|---|---|---|
| 把读 skill 当成已经执行，创建时仍依赖默认值，审查又只覆盖产品内容 | 已有背景、组件或绑定规则仍被漏掉，容器和未验收项被报为完成 | 按上节建立规则与动作、证据、状态的对应关系；本轮明确漏项返回执行修复，不停在只读报告 |
| 没有先区分需求、原型、旧稿、线上各负责什么 | 把旧稿当线上，保留已下线操作，字段和状态画错 | 修改前按 [来源分工](live-alignment-verification.md#先分清依据负责什么) 确定依据；用户后来指定线上时更新基准，不沿用已被否定的旧结论 |
| 将原型差异一律当作改动要求，或为完整性补写文案 | 通用字段被改名、换样式，产品多出无依据说明 | 按主 skill 的 [字段与文案保护](../SKILL.md#通用字段通用样式与文案保护) 区分明确变化、沿用和冲突；通用内容以适用现行稿保留，变化限定到对象及属性，新增或改写文案核原文来源或明确创作授权；在既有集中检查中反查实际变化，不另建台账或审批 |
| 需求只拆页面和可见字段，把提示说明当次要文案；验收只看默认态 | 漏 Tooltip、只留问号、正文提示未落稿；把静态交付误当成无需展开态 | 提示说明独立建项，从来源逐项对应到触发入口、完整文案、必要状态和验收证据，按下节执行 |
| 把复制或改字当作完成，不理解复合组件和展示条件 | 图文退化为纯文字、富文本失去分段样式、出现不适用的默认操作 | 复用完整组件，保留样式分段与业务条件，按 [内容修改边界](live-alignment-verification.md#只改内容时保留组件样式与使用条件) 验证 |
| 用坐标或残留固定尺寸维持布局，只看外框 | 表格和分页断开、按钮距离过大、删内容后留空洞 | 检查真实布局链、内容高度及相邻可见边缘；修正产生空隙的容器规则，不用占位或局部位移遮盖 |
| 按名称、属性或数字正常判断视觉正确 | 半选样式、标签色、线宽、阴影和图标仍不对 | 同时对照实际绘制层与本机截图，不能用绑定正常、组件存在否定可见差异 |
| 把数据组合和操作过程当作设计状态 | 同一页面因数据组合或过程差异被重复复制 | 仅实际布局、控件或必要状态不同才保留独立表达，按 [状态收敛](app-pc-rules.md#范围与展示去重) 处理 |
| 一次只补用户圈出的点，忽略同因范围和后来例外 | 同一字段有的改了有的没改；列表规则误套到详情 | 建立反馈覆盖记录，逐类检查适用页面，后续更具体纠正优先，不作无差别替换 |
| 批量改后只读属性、只看缩略图，失败后直接重跑 | 漏图、裁切、叠线、重复节点及未验证稿被报为完成 | 分批完成修改、读回和截图；失败先检查实际结果，仅补未完成部分，最终按证据汇报 |

这些是执行过程的失误，不能归咎于用户没指出位置，也不能把全部视觉问题未经核实归因于 Bridge 或字体缓存。

## 提示说明防遗漏

1. **从来源拆项，不能只看首屏**：完整读完需求正文、表格与验收项后，再核 HTML 的相关提示节点与触发逻辑；检查 Tooltip、帮助／问号／信息图标、悬停或点击说明、禁用原因及条件出现的提示。关键词、`title`、`data-*` 和事件处理可辅助查找，不能代替阅读上下文；默认截图没显示不能作为没有提示的依据。
2. **每条提示有对应关系**：在工作记录中维护「来源章节／原型位置 → 适用端与页面／字段／入口 → 展示条件与触发方式 → 完整文案及动态值 → 对应设计节点／状态 → 验证结果」。同一说明复用时可共用内容记录，但要列全本轮适用入口；不能只写“补 Tooltip”。这份记录不额外塞进产品界面。
3. **业务说明与评审备注分开**：先执行主 skill 最高优先级原则，不新增布局已能解释的辅助标签和重复说明。需求明确要求、且用户完成操作所必需的规则、数据口径、限制和禁用原因须有设计承载；不以该原则省略必要业务提示。原型的评审导航、演示注释和开发备注不默认画进产品。正文与 HTML 冲突或必要提示文案缺失时查明来源；无法查明的项标为待确认，不自行编造、删掉或算作已完成。
4. **入口与内容一起落稿**：按所属库用法及同功能现行稿复用 Tooltip／Popover 等组件，核准确文案、分段、条件显隐与锚点。只画问号、只开启说明布尔属性、沿用组件占位文案，或只在库里找到组件，都不算完成业务说明。
5. **静态稿也表达必要展开态**：需要提示说明的地方保留入口，并在对应真实页面上下文中表达可读的展开状态；按 [无遮罩浮层展示](app-pc-rules.md#弹窗抽屉与浮层) 定位，不为每条提示机械复制整页，不把独立组件样例当作业务交付。默认不新增原型连线。PC 悬停与触屏端按来源规定的触发方式分别表达，不擅自把 hover 行为搬到移动端。
6. **用来源清单反查最终稿**：逐项核入口、完整文案、条件与展开态，再查箭头、锚点、换行、裁剪、遮挡及完整浮层边界；读回内容并看最后一次修改后的实际渲染。逐一覆盖本轮适用页面和不同提示内容，不能以一张浮层正确代表全部通过。删字段、换组件或合并状态后重核提示是否仍在正确入口。
7. **未覆盖不能报完成**：每项明确为已验证、明确不适用（附依据）或未验证（附缺口）；尚未落稿与尚未验收分别说明，不留无结论的清单项。用户补出遗漏时，先修已授权位置，再复核本轮同因入口，不扩改无关历史稿。

## 修改前与修改中的约束

- **先定允许变化与保留项**：明确本次修改内容、状态、样式还是结构，并限定对象与属性。未被本次变化涉及的文案、单位、按钮角色／顺序、行列内容、组件整体及嵌套关联、图片、分段样式、颜色绑定、尺寸和布局默认保留；内容增减必需的空间调整可在授权范围内处理，但不得借机改变信息分组或整体风格。新设计没有现成基准时，在已授权方向内形成方案，不要求用户提供每个像素值。
按实际操作选择下表核对项，复用 [本轮视觉必检项](#本轮涉及的视觉必检项) 及适用引用，不重复建表或逐节点截图。会扩大错误的异常即时处理，其余结果并入功能批次的集中检查；本表不授权新增状态、组件能力或范围外改动。

| 实际操作 | 修改与核对要求 |
|---|---|
| 复制、替换组件或图标 | 从真实母组件及实际造型核来源，复用完整图文、操作组、表格或弹窗结构，不只取文字层或底层按钮；整页复制按主流程先核完整画板及页面框架，局部替换须保留原父容器关系，不用通用模板覆盖现行布局；核图片、嵌套关联、Slots、变量、主题和实例覆盖，并核当前业务条件是否应展示自带入口。名称相同或底层实例存在不能证明复用正确 |
| 修改文字、金额或链接 | 先核变更依据及准确文案来源，不因原型示意差异替换通用字段，无明确文案创作授权时不自行补写或润色；核完整文案、数值、精度、空格、单位与链接，保留富文本逐段字体、字号、颜色、样式及绑定，不将整段统一赋值；金额补币种继续按主规则例外执行，不把指定内容恢复成旧稿漏写状态 |
| 切换变体、属性、显隐或插槽 | 重新读取实际内容、条件、选中／半选表现、图标、嵌套覆盖和布局，核默认值是否重置了已确认内容；恢复可见区域时检查其全部受影响子层，不以属性名称或外层关联代替实际状态 |
| 调整容器、尺寸或布局 | 正文用自动布局，浮层依附真实页面与触发点；核父子层 Hug／Fill／固定、内边距、间距、隐藏项、空占位及相邻衔接。父容器变尺寸时核背景约束、图片几何、投影与裁剪，区分合法滚动视口／底部留白和异常空洞，不把全部容器改成 Hug。线条变粗先查叠边、缩放和重复层，阴影先查所属层、方向和裁剪，不挪坐标、减线宽或换颜色掩盖根因 |
| 删除、去重或定稿回迁 | 删除前核独有内容、必要状态、隐藏节点及组件依赖；回迁核目标端／版本／语言、真实模块和已有能力，只补缺失。操作后核保留项、父子关系、完整边界及残留动作，不凭名字或数量删除。沿 [还原与迁移](restoration-migration.md) 执行，不能因“补齐”放宽范围与状态限制 |
| 修改共享母组件或库能力 | 先核真实归属、授权与影响范围，保留已有能力和业务覆盖；修改后核相关变体与业务实例。按 [库验收](figma-libraries.md#复制与更新验收) 分别确认母组件修改、用户发布、实例更新、本机验证和云端保存，不能把源稿正确推断为消费者已同步 |

- **反馈记录留在工作记录**：按「用户纠正 → 错误属性与当前依据 → 同因适用页面／组件 → 明确例外 → 已修／已验证／未验证」维护。先定位差异再修改；同因覆盖不扩大允许变化的属性，不把局部宽度问题变成列数重排。用户后续新选择更新基准，不倒推为最初漏需求。不把检查表画进产品界面。

## 本轮涉及的视觉必检项

只检查任务中存在的项目；表中同类复核限本轮产出及同因受影响稿，不授权改无关历史稿或共享库。

| 对象 | 验收要求 |
|---|---|
| 基于源稿的页面框架 | 对照完整源画板核顶部导航、各级侧边菜单、内容区、侧栏及底部区域；保留项的存在、显隐、展开／选中、父子关系、相对位置、尺寸及实际样式均须一致或有明确变化依据。不能只查新增模块、层数或无重叠；隐藏、折叠、裁切及移出画板同样属于变化，发现框架失真先停止依赖它的批量派生，核清并局部恢复本轮误改 |
| Section 与外层容器 | 本轮创建、复制或修改的 Section 按 [背景规则](figma-workflow-tools.md#section-背景) 逐个核实际填充和绑定，并截图包含分区边界；不只验里面的画板，不改产品内容底色 |
| 自动布局与空隙 | 正文、表格和按钮组按布局关系衔接；读实际可见内容边缘之间的距离，不能只看间距字段。分页跟随末行的细则见 [表格衔接](table-design-rules.md#内容分页与行粒度) |
| 图文单元格 | 既有图文组件保留缩略图、文本和原排列；确认图片实际加载、可见且未被裁切，不以图片字段存在代替有图 |
| 选择控件 | 未选、全选、半选使用所属库真实状态；半选不以文字短杠、手画符号或全选勾号替代。核对选中背景、标记形状、边框和尺寸 |
| 表格数字与操作组 | 金额、价格、数量的表头及数据右对齐；编号不作为数量。固定规则、阴影及按钮间距见 [操作列](table-design-rules.md#对齐与操作列) |
| 链接与占位 | 可跳转编号使用正确链接样式，同一语义与条件下统一；不把所有编号一律变蓝。无数据占位沿本轮指定来源，不擅自统一成其他符号；占位无目标时不画为链接 |
| 标签与图标用色 | 标签沿用对应语义色，品牌标识使用其已确认用色，帮助图标与固定图标分别核对现行稿；不统一刷主色，也不凭变量名推定实际颜色正确 |
| 页签与按钮变体 | 从同功能来源复用完整控件并核实际选中态；场景已确认的控件类型不被通用偏好误覆盖，不将局部例外推广到所有控件 |
| Tooltip 与浮层 | 核触发入口、准确说明、箭头、间距、投影和完整边界；Tooltip 通常在触发点上方，空间不足或指定参考有明确例外时按实际处理，不一律置顶。漏说明和只补问号都不合格 |
| 条件操作与数据 | 从当前适用线上场景核实是否应展示，不能因旧组件自带就保留操作。相关数值、状态和计数按已确认口径一起核，不能凭示例值或日期反推 |
| 状态与整页去重 | 同页同内容归同一 Section；示例值、选择数量或浮层变化不默认增加整页。合并前保留独有内容和必要状态，去重后核组件依赖及布局；不按名字或画板数量判断重复 |
| 静态设计交付 | 不为演示点击复制整页或制作连线。遮罩弹窗和无遮罩浮层的展示分别按 [展示方式](app-pc-rules.md#弹窗抽屉与浮层)；原型清理按主 skill 验证 |

## 交付条件：把规则落实为证据

先核 [规则执行记录](#规则执行闭环)：每条本轮适用规则都有对象、动作、结论和对应证据。“已读”“工具成功”不作为执行或验收结果；待执行、待验收及阻塞项须明确列出，不包含在完成范围内。

1. **来源对照**：本轮每类改动有可追溯的当前依据；无法访问的来源或不能复现的状态明确记为未验证。
2. **结构与内容读回**：按来源清单核完整字段／行内容、业务正文及必要状态，排查未替换的默认占位；核组件与嵌套关联、实际变体、条件显隐、文本分段及生效布局。适用时用批量对账检查文案、尺寸、关联、绑定和多余稿；行数或节点数量相同不能代替内容一致，不为单点低风险改动建设无关测试框架。
3. **本机视觉复核**：最后一次修改后，同时看完整页面上下文与关键区域正常比例截图，覆盖不同布局及本次涉及的必要状态；缩略概览不能验线宽、半选、颜色和富文本。
4. **同因覆盖**：反馈覆盖记录中所有适用项均有结果，明确例外未被误套；本轮已有完整表格展示与页面内表格一起核，不残留旧状态。
5. **布局与去重**：重核内部衔接、浮层锚点及完整可见边界，再核画板和 Section 排布。设计内有意叠放与独立展示区域碰撞区分；最后尺寸变化使先前验收失效。
6. **集中走查与真实汇报**：按 [设计走查人员](design-reviewer.md) 将内容、视觉与结构合并检查，复杂任务可拆给 Agent 4、Agent 3，替代原有两轮完整往返；最终收口复用仍有效的结论，只补跨批与未验证项，不再做相同的整轮验收。只声明实际验证的范围，未截图、未连接、未同步分别说明；不以“已执行”或各角色均称完成代替“已验证”。
